# Data flow and credentials

Projects, case files, run metadata, and results are stored locally. OpenFOAM runs in local Docker. AI requests can send conversation text, relevant case contents, tool results, diagnostic logs, and retrieved documentation to the selected provider. Cloud modes therefore do not keep all simulation information on the machine. Compatible endpoints send data to the configured URL; whether that endpoint is local depends on the user configuration. Check the provider's retention/training policy before sending sensitive material.

The packaged Electron app stores provider keys in an encrypted local credential file using Electron safeStorage and the operating system credential facility. Encryption depends on the system keychain; startup fails clearly if encryption is unavailable. Core code has no Electron dependency and uses an injected credential adapter via Node IPC. Legacy plaintext config is migrated only after encrypted storage succeeds. Headless/source mode without Electron retains restricted-permission local config storage; it does not claim OS-backed encryption.

Settings returns key-presence flags, never key values. Explicit removal clears the saved key and active process environment and persists a removal mask to prevent inherited environment variables silently restoring it. Changing a shell's environment or deleting the application's saved key does not revoke a provider-side credential; revoke or rotate through that provider when needed.

Codex uses its own authentication. The app requests ephemeral, read-only, tool-disabled CLI sessions with supplied case context and structured proposals; the app validates and applies changes. See the [official CLI reference](https://learn.chatgpt.com/docs/developer-commands?surface=cli). CLI state outside the app may still contain authentication/cache data. The selectable Claude Code CLI integration uses its own authentication and can retain transcripts/caches independently. See its [data controls](https://code.claude.com/docs/en/data-usage). The app does not automatically purge external CLI state. Backups and exported support material can contain simulation details; inspect and redact them before sharing. Do not attach credential files or raw configuration files to issues.
